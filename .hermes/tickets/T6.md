## Parent

[#16 — Spec: GitHub API data integration](https://github.com/davidsilva131/gh-dash/issues/16)

## What to build

Wire everything together in the Dashboard component. The Dashboard becomes the orchestrator: it manages the fetch lifecycle (`useState` for `data`, `isLoading`, `error`), calls the API endpoint on username change (with AbortController to cancel stale requests), validates usernames client-side (GitHub-compatible regex), and passes real data down to all four tabs.

This is the ticket where gh-dash becomes a real dashboard — typing a GitHub username renders actual GitHub data in all four tabs. The hardcoded SAMPLE_* fallbacks are removed from the production code path (they remain in test fixtures). The 29 existing tests keep passing because tabs accept data via props.

## Acceptance criteria

- [ ] Dashboard fetches `/api/github/{username}.json` on username submit (not on every keystroke)
- [ ] Username validation on submit: non-empty + matches GitHub username regex (`/^[a-zA-Z0-9](?:[a-zA-Z0-9]|-(?=[a-zA-Z0-9])){0,38}$/`). Invalid input shows inline validation feedback without making a network request
- [ ] AbortController cancels the previous in-flight request when a new username is submitted
- [ ] Dashboard state: `idle` (no search yet) → `loading` (fetch in flight) → `success` (data returned) or `error` (API returned an error)
- [ ] On success, passes `data` to all four tabs; each tab renders real GitHub data
- [ ] On error, passes `error` to all four tabs; each tab renders the error UI from T4
- [ ] On loading, passes `isLoading=true` to all four tabs; each tab renders the skeleton from T4
- [ ] SAMPLE_* fallback code removed from production components (imports from fixtures.ts remain for tests only)
- [ ] All 29 existing tests pass (`pnpm test`)
- [ ] Dashboard orchestration tests: submitting a username triggers fetch, successful fetch renders data in tabs, error response renders error UI, retry on network error triggers a new fetch, submitting a new username aborts the previous request
- [ ] E2E verification: start dev server (`pnpm dev`), type a real GitHub username → all 4 tabs render real data (profile, repos, events, charts). Type a nonexistent username → "User not found" error
- [ ] `pnpm build` succeeds
