## Parent

[#16 — Spec: GitHub API data integration](https://github.com/davidsilva131/gh-dash/issues/16)

## What to build

Create the shared TypeScript type definitions for all GitHub data shapes consumed by the dashboard, and extract the hardcoded sample data from the four tab components into a shared test fixture file. All 29 existing tests must keep passing — this is a no-behavior-change prefactoring that makes subsequent data-layer work safe.

The types serve as the single contract between the service layer (coming in a later ticket) and the UI components. The fixture serves as the single source of truth for all test data, replacing the scattered `SAMPLE_*` constants currently defined inside OverviewTab, ReposTab, ActivityTab, and ChartsTab.

## Acceptance criteria

- [ ] `src/lib/types.ts` exports `GitHubUserData`, `Repo`, `ActivityEvent`, `Language`, and `ErrorState` types matching the shapes from the parent spec
- [ ] `src/test/fixtures.ts` exports `SAMPLE_USER_DATA`, `SAMPLE_REPOS`, `SAMPLE_EVENTS`, `SAMPLE_LANGUAGES`, `SAMPLE_STARS`, and `SAMPLE_ACTIVITY` matching the new types
- [ ] All 29 existing tests import from `src/test/fixtures.ts` instead of referencing internal component constants
- [ ] All 29 tests pass (`pnpm test`)
- [ ] `pnpm build` succeeds with no TypeScript errors
