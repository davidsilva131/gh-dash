## Parent

[#16 — Spec: GitHub API data integration](https://github.com/davidsilva131/gh-dash/issues/16)

## What to build

Add optional `data`, `isLoading`, and `error` props to the four tab components (OverviewTab, ReposTab, ActivityTab, ChartsTab). When no props are provided, each tab falls back to its internal `SAMPLE_*` data — guaranteeing backward compatibility and keeping the existing 29 tests green without modification.

Each tab gains a three-way rendering branch: loading (placeholder text), success (current content), error (placeholder text). The visual skeleton and error components themselves arrive in a later ticket; this ticket establishes the prop interface and the rendering contract.

## Acceptance criteria

- [ ] Each tab component's Props interface gains optional `data?: GitHubUserData`, `isLoading?: boolean`, and `error?: ErrorState | null` fields
- [ ] When `isLoading` is true, the tab renders a loading placeholder (text-only is acceptable)
- [ ] When `error` is set, the tab renders a basic error message (text-only is acceptable; styled error UI comes later)
- [ ] When `data` is provided, the tab renders the real data (ignoring internal SAMPLE_*)
- [ ] When no props are provided (undefined/omitted), the tab renders exactly as it does today using internal SAMPLE_* — the current behavior is unchanged
- [ ] All 29 existing tests pass without modification (`pnpm test`)
- [ ] New tests cover: rendering with explicit `data` prop, rendering with `isLoading=true`, rendering with each `error` type
- [ ] `pnpm build` succeeds
