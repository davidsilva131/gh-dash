## What to build

Build the server-side GitHub data service: a single function `fetchGitHubUser(username, token, abortSignal) → GitHubUserData` that fetches profile, repos, languages, contributions (via GraphQL) and recent events (via REST) from the GitHub API, transforms the raw responses into typed `GitHubUserData`, and caches results in-memory with a 5-minute TTL.

The service classifies errors into three types: `not_found` (404 — username doesn't exist), `rate_limited` (403 with exhausted rate limit), and `network` (timeout, DNS failure, or unexpected HTTP status). The module is pure logic — no Astro imports, no UI, no HTTP server.

## Acceptance criteria

- [ ] `src/lib/github.ts` exports `fetchGitHubUser(username: string, token: string, signal?: AbortSignal): Promise<GitHubUserData>`
- [ ] On success, returns `GitHubUserData` with profile, stats, languages, contributions, repos, and activity matching the types from T1
- [ ] GraphQL query fetches profile, first 30 repos, languages, and contribution collection in a single request
- [ ] REST call fetches `/users/{username}/events/public` (up to 100 events) in parallel with GraphQL via `Promise.all`
- [ ] In-memory `Map` cache keyed by lowercase username; second call within 5 minutes returns cached data with zero fetch calls
- [ ] GitHub 404 on either endpoint → throws/returns `not_found` error
- [ ] GitHub 403 with `x-ratelimit-remaining: 0` → `rate_limited` error with reset timestamp
- [ ] Network failure or timeout (>10s via `AbortSignal.timeout`) → `network` error
- [ ] Abort signal cancels both in-flight requests when triggered
- [ ] Unit tests mock `global.fetch` and cover: success with transformation, 404, 403 rate-limit, network error, cache hit/miss/expiry, abort propagation
- [ ] `pnpm test` passes for the new module
