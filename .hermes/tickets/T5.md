## What to build

Create an Astro API endpoint at `GET /api/github/[username].json` that wraps the data service from T3. The endpoint reads the `GITHUB_TOKEN` from server-side environment, calls `fetchGitHubUser`, and returns JSON. The token is never exposed to the browser — this is a server-side-only route.

The endpoint is a thin wrapper: it validates the username parameter, delegates to the service, and serializes the result or error as JSON. No caching logic here — the service owns that. No UI — just a JSON contract the Dashboard will consume in T6.

## Acceptance criteria

- [ ] `src/pages/api/github/[username].ts` (or equivalent Astro endpoint pattern) handles GET requests
- [ ] On success, returns HTTP 200 with `{ profile, stats, languages, contributions, repos, activity }` matching `GitHubUserData` shape
- [ ] On user not found, returns HTTP 404 with `{ error: { type: "not_found", message: "..." } }`
- [ ] On rate limit, returns HTTP 429 with `{ error: { type: "rate_limited", message: "...", retryAfter: "..." } }`
- [ ] On network/service error, returns HTTP 502 with `{ error: { type: "network", message: "..." } }`
- [ ] Reads `GITHUB_TOKEN` from `import.meta.env.GITHUB_TOKEN` (server-side); returns 500 with a clear message if missing
- [ ] Verifiable with `curl`: `curl http://localhost:4321/api/github/torvalds.json` returns real data (when GITHUB_TOKEN is set and dev server is running)
- [ ] `pnpm test` passes (no breaking changes to existing suite)
- [ ] `pnpm build` succeeds
