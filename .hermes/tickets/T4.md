## What to build

Replace the placeholder text in the tab loading and error branches (from T2) with real skeleton animations and error UI components.

Loading state: each tab renders pulsing skeleton cards matching the shape of the real content — stat cards, language bars, contribution grid, repo cards, activity rows, and chart placeholders.

Error state: a reusable `ErrorDisplay` component handles three error types — `not_found` shows a "User not found" message with a hint to check the username, `rate_limited` shows a "Rate limit hit" message with a countdown timer to the reset time, and `network` shows a "Could not reach GitHub" message with a Retry button.

## Acceptance criteria

- [ ] A `Skeleton` component (or shadcn-style pulsing bars) renders for each data section: stat cards (3), language bars (5), contribution grid (52x7 cells), repo cards (5), activity rows (6), and charts (3 rectangles)
- [ ] A reusable `ErrorDisplay` component accepts `error: ErrorState` + optional `onRetry` callback
- [ ] `not_found` renders: "User not found" heading + "Check the username and try again" hint
- [ ] `rate_limited` renders: "Rate limit hit" heading + "Try again in X minutes" with a live countdown based on the `retryAfter` field
- [ ] `network` renders: "Could not reach GitHub" heading + "Check your connection" text + a visible, clickable Retry button
- [ ] Each tab replaces its T2 placeholder text with the real skeleton and error components
- [ ] Component tests per tab verify: loading → skeleton elements visible in the DOM, error → correct error message and type-specific UI visible, network error → retry button present
- [ ] All 29 existing tests still pass (`pnpm test`)
- [ ] `pnpm build` succeeds
